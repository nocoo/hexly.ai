# 首批 README 模板

模板取自 Snaky 的居中品牌头部与面向使用者的章节结构。统一信息顺序，内容长度按项目复杂度决定；不为凑章节添加空内容。

## 头部

保留仓库已经采用的 Logo，不重新制图。中文根 README 使用根目录相对路径；英文版位于 `docs/README.en.md`，图片、源文件和许可证链接按这个位置重写。

```html
<p align="center">
  <img src="logo.png" width="128" alt="Project logo" />
</p>
<h1 align="center">Project</h1>
<p align="center">一句话说明给谁使用、解决什么问题。</p>
<p align="center">
  <a href="https://verified.example">站点</a> ·
  <a href="docs/README.en.md">English</a>
</p>
```

没有站点时删除站点链接和分隔符；不把本地开发地址写成线上站点。英文版的同一位置显示 `Website · 简体中文`，中文回链为 `../README.md`。如保留状态 badges，只保留有实际来源且便于维护的标识，不硬编码测试数和覆盖率。

## 正文顺序

| 中文章节 | 英文章节 | 应回答的问题 |
| --- | --- | --- |
| 这是什么 | What it does | 目标使用者、具体问题、项目运行形式与适用边界 |
| 功能 | Features | 现在已经能完成什么；按用户任务组织，必要时标明平台条件 |
| 使用 | Usage | 普通使用者怎样安装、打开或执行最小示例 |
| 开发 | Development | 实际运行时、依赖安装、必要配置、本地启动 / 构建；复杂部署链接到专门文档 |
| 测试 | Tests | 仓库实际存在的各层测试运行方法和必要前置条件 |
| 技术栈 | Stack | 主要语言、UI、服务、数据 / 存储与测试工具；说明各自用途 |
| 文档 | Documentation | 指向有用且仍然有效的使用、架构、部署等文档 |
| 许可证 | License | 从实际 LICENSE 读取，不推断许可证 |

安装较复杂的 CLI / 桌面项目可在「使用」下分「安装」「常用命令」。纯服务或组件模板可直接在此提供启动 / 集成示例。目录结构只保留帮助读者找代码的主要路径，可以放在开发章节中。

## 内容核实

1. 先核对 Git 分支和工作区，安全 pull 后记录 SHA。
2. 阅读 README、项目维护说明、包配置、入口、功能实现、测试和发布脚本。
3. 用代码定位证实关键功能；旧文档与代码冲突时记录差异，按当前代码改写。
4. 从 manifest / lockfile 确认技术栈，从实际脚本确认命令，从站点配置或仓库元数据确认链接。
5. 中英文写相同事实、同一组示例和前置条件，避免英文版只是摘要。
6. 检查链接、路径、示例与测试入口。必要时实际执行安全、隔离的构建与测试；记录执行范围。

测试章节不讲 6DQ，也不移入 hook 制度、覆盖率门槛、质量门禁或发布流程。对尚未实现的测试层不编造命令。不要把“有脚本”写成“验证通过”。

## 写作约束

用具体能力说明价值，例如“将直接连接与代理连接的出口 IP 并排显示”，避免“强大、极致、企业级、无缝”。能确认的限制直接写清，例如所需操作系统、受支持后端、离线数据范围。正式 README 不夹带本轮调查过程；调查过程保留在本站 docs。

技术栈优先写不容易过时的技术名称。只有安装 / 运行会受影响的版本要求才写清最低版本，并提供来源；不逐项复制 lockfile 版本。

## 本站字段

仅在完整核实并整理双语 README 后添加可选的 `overview`。首批只填写 Snaky、Steed；其余项目缺少该字段时不显示空资料块。

```json
{
  "overview": {
    "goal": { "en": "The specific user goal.", "zh": "具体的用户目标。" },
    "techStack": [
      { "name": "TypeScript", "role": { "en": "CLI", "zh": "命令行" } }
    ],
    "verified": {
      "date": "2026-09-08",
      "revision": "40-character-commit-sha",
      "sources": ["package.json", "src/index.ts"]
    }
  }
}
```

`verified.revision` 指完成代码调查时的提交。README 整理提交另记在交付记录中；原有 `source` / `logo` 的视觉来源保持其对应提交。技术栈的名称使用通用专名，用途提供中英文。`verified` 供文档追溯，界面只显示目标、技术栈和相应语言 README 的入口。

详情页的资料块放在第一组大图下方、设计说明上方，继续保持跨项目切换时大图位置稳定。英文 HTML 静态快照同步包含目标和技术栈；客户端切换语言显示完整的对应翻译。
